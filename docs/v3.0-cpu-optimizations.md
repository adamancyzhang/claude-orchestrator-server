# V3.0 CPU Utilization Optimization

## Summary

Optimized CPU usage in the orchestrator and infra packages to improve performance and reduce resource consumption.

## Changes Made

### 1. Resource Monitor Optimizations (`packages/infra/src/resource-monitor.ts`)

**CPU Calculation Optimization:**
- Cached CPU count on construction to avoid repeated `os.cpus().length` calls
- Optimized CPU time iteration to use direct property access instead of `for...in` loop
- Pre-calculated CPU times for faster delta computation

**Alert Deduplication:**
- Added 60-second cooldown window for alerts
- Prevents alert flooding when thresholds are continuously exceeded
- Reduces unnecessary callback invocations and logging

**ESM Compatibility Fix:**
- Fixed incorrect `require("node:fs")` usage in ESM context
- Added proper type assertion for dynamic import

### 2. Message Batcher Optimizations (`packages/infra/src/message-batcher.ts`)

**Array Reference Optimization:**
- Changed from array copy (`[...this.currentBatch]`) to reference swap
- Reduces memory allocation and garbage collection pressure
- Improves throughput for high-volume message processing

## Performance Impact

### Before Optimization
- CPU calculation called `os.cpus()` and iterated with `for...in` on every snapshot
- Alerts fired on every threshold check, causing callback overhead
- Message batcher created new arrays on every flush

### After Optimization
- CPU count cached, iteration optimized with direct property access
- Alerts deduplicated within 60-second windows
- Message batcher uses reference swaps instead of copies
